START HERE · HOW MUCH PLANNING IS ENOUGH?

Decompose only as far as the work needs

Choose the simplest useful pattern. Heavier process is not more mature. Bias toward the lightest Planning Depth and Method that can credibly satisfy the Contract; then learn from measured results.

Planning depth

L1

Product/System baseline iDurable capability and architecture context. Most normal loops reference it rather than recreate it.

Established early or reconstructed when adopting an existing system.

L2

Execution increment iA bounded deliverable meaningful enough to validate on its own.

The common unit for an ongoing work loop.

L3

Executable tasks iDependency-aware implementation and test/eval tasks that a coding agent can execute against.

Produced during Planning for the selected increment.

L4

Agent micro-plan iLocal implementation steps chosen during execution; usually ephemeral unless they reveal a durable decision.

The agent controls this within approved boundaries.

Planning Method is a mandatory choice—and an experiment

Lightweight / agent-led iTiny, well-understood, low-risk changes where one clean run is plausible.

Explicit task plan iNormal feature/change work with predictable decomposition and dependencies.

Vertical slices iProduct work where independently usable behavior and early Validation matter.

Dependency-first iGreenfield, platform, infrastructure, or migration work with true prerequisites.

Rolling-wave iUncertain work: plan the near term deeply and elaborate later work only when useful.

Spec-of-specs iWork too large for one Plan/context; split into independently planned sub-features.

Orchestrator-worker iComplex work whose exact subtask structure cannot be confidently predicted up front.

Evidence/test-first iCrisp behavior, regressions, APIs, security, and reliability work where feedback quality drives outcome quality.

Learning loop: record work type, Planning Depth/Method, model placement, quality, cost, human time, retries, and rework. System memory should improve future recommendations.
