Knowledge & Context

Context is finite. Projects are not. Knowledge & Context lets work continue reliably without stuffing the whole history into every model call.

What it is

System-owned memory plus fresh, task-specific context.

Why it matters

The context window is not a system of record.

Failure prevented

Context landfill, stale summaries, session dependence, and wasted model capacity.

Core philosophy

Fresh context and progressive elaboration beat endless conversation.

Memory is a portfolio

agent.md / soul.md iagent.md can hold operational guidance; soul.md is a local convention for personality and interaction behavior. Neither overrides Contract, authority, or Proof.

Standing agent instructions and interaction style.

LLM Wiki / knowledge base iDurable architecture, decisions, standards, lessons, and product knowledge live outside active model context and are retrieved when needed.

Agent-accessible durable knowledge.

Structured handoff packs iCurrent task, decisions, changes, evidence, blockers, source pointers, next action, and stop/escalation condition for the next worker.

Deliberate continuation state.

Glass-of-water model: context pre-fills the glass before work begins. Fill it with enough high-signal information to make the agent smart on the task—but every unnecessary token consumes room for reasoning, tool results, and new work.
Economic design: model placement is also an experiment. Test budget, local, specialist, and frontier models by task type and phase; preserve quality/cost/rework results so routing improves over time.
