Planning

Planning exists because “break the work into tasks” is unsafe if the planner does not first understand the system those tasks will change.

Choose the simplest useful pattern. Heavier process is not more mature. Increase planning depth, review, model capability, and orchestration only when task shape or evidence warrants it.

What it is

Architecture-aware solution design: orient to the Contract, current architecture/codebase, and existing Architecture Decision Records (ADRs) iA durable record of an architecturally significant decision: context, options, rationale, and consequences.; then choose architecture, verification, decomposition, tasks, dependencies, and execution pattern.

Why it matters

A coding agent can solve one ticket beautifully while damaging the whole system.

Failure prevented

Architecture-blind decomposition and hidden coupling.

Core philosophy

Tasks are the output of system understanding—not a substitute for it.
