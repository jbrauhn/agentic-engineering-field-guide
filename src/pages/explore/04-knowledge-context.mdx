Context is finite. Projects are not. Knowledge & Context lets work continue reliably without stuffing the whole history into every model call.

  <div className="card"><h3>Why it matters</h3><p className="muted">The context window is not a system of record.</p></div>

## Memory is a portfolio

<div className="grid three">
  <div className="card"><h3>agent.md / soul.md <InfoTip label="agent.md and soul.md">agent.md can hold operational guidance; soul.md is a local convention for personality and interaction behavior. Neither overrides Contract, authority, or Proof.</InfoTip></h3><p className="muted">Standing agent instructions and interaction style.</p></div>
  <div className="card"><h3>LLM Wiki / knowledge base <InfoTip label="LLM Wiki or knowledge base">Durable architecture, decisions, standards, lessons, and product knowledge live outside active model context and are retrieved when needed.</InfoTip></h3><p className="muted">Agent-accessible durable knowledge.</p></div>
  <div className="card"><h3>Structured handoff packs <InfoTip label="structured handoff pack">Current task, decisions, changes, evidence, blockers, source pointers, next action, and stop/escalation condition for the next worker.</InfoTip></h3><p className="muted">Deliberate continuation state.</p></div>
</div>

<div className="quote"><strong>Glass-of-water model:</strong> context pre-fills the glass before work begins. Fill it with enough high-signal information to make the agent smart on the task—but every unnecessary token consumes room for reasoning, tool results, and new work.</div>

<div className="callout"><strong>Economic design:</strong> model placement is also an experiment. Test budget, local, specialist, and frontier models by task type and phase; preserve quality/cost/rework results so routing improves over time.</div>
