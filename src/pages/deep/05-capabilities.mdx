<span className="pill purple">How it works</span>

## Purpose
Let AE runtimes use source control, continuous integration/continuous delivery (CI/CD), sandboxes, databases, observability, identity, and business systems without making the method dependent on one product.

## Implementation options
Direct governed product integration, application programming interfaces (APIs), Model Context Protocol (MCP), enterprise brokers, or organization-specific adapters.

<div className="quote">Open interfaces; organizational tool choice.</div>

## Key property
The Plan describes needed capability semantics and evidence; installation determines how the organization fulfills them.
</section>
<section className="pane">
<span className="pill blue">How we work</span>

## During installation
Map AE capabilities to the organization’s real systems: source control, work tracker, CI/CD, runtime or sandbox, secrets, identity, telemetry, and deployment.

## During Planning
Select only the capabilities required for the work and define expected evidence and authority.

## During Execution
Use the organization’s approved integration path. Tool results are observations/evidence and should be traceable to the task.

## Portability
An organization can use GitHub directly, route through brokers, or implement adapters. The AE method should remain unchanged.
