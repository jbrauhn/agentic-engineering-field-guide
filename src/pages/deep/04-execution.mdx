## Boundaries
Execution may adapt local implementation inside the reviewed Plan. If a Plan assumption fails, route to Planning. If the target should change, submit a Contract proposal.

## Patterns
- single-agent iterative loop;
- fresh-agent relay;
- parallel independent workers;
- Maker → Checker;
- coordinated multi-agent orchestration.

## Give the worker
A bounded L3 task or L2 increment, relevant Contract + architecture + dependencies, fresh context/handoff, allowed capabilities and authority, and required evidence hooks.

## Worker behavior
Use tools, inspect feedback, test continuously, retry where reasonable, capture state, and stop or escalate when evidence says the boundary or Plan is wrong.

## Maker → Checker
Maker → Checker is a useful **execution topology**. It does not replace lifecycle Validation against Contract Proof.

## Open experiment
Whether Execution Loop deserves its own reusable skill remains intentionally unresolved; validate the pattern through real work rather than declaring it universal up front.
