Capability Interfaces

How it works

Purpose

Let AE runtimes use source control, CI/CD, sandboxes, databases, observability, identity, and business systems without making the method dependent on one product.

Implementation options

Direct governed product integration, application programming interfaces (APIs), Model Context Protocol (MCP), enterprise brokers, or organization-specific adapters.

Open interfaces; organizational tool choice.

Key property

The Plan describes needed capability semantics and evidence; installation determines how the organization fulfills them.

How we work

During installation

Map AE capabilities to the organization’s real systems: source control, work tracker, CI/CD, runtime/sandbox, secrets, identity, telemetry, and deployment.

During Planning

Select only the capabilities required for the work and define expected evidence/authority.

During Execution

Use the organization’s approved integration path. Tool results are observations/evidence and should be traceable to the task.

Portability

An organization can use GitHub directly, route through brokers, or implement adapters. The AE method should remain unchanged.
