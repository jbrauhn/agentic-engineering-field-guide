GO DEEPER · SYSTEM-OWNED MEMORY

Knowledge & Context

How it works

Memory layers

  1. Durable knowledge / system of record — architecture, standards, decisions, lessons.
  2. Workflow state — current Plan/tasks/artifacts/risks/approvals.
  3. Architecture/code graph — components, interfaces, dependencies.
  4. Structured handoff pack — deliberate continuation state.
  5. Fresh agent context — the smallest trustworthy slice needed now.
The agent does not own memory; the system owns memory. Agents read and write under rules.

Candidate mechanisms

agent.md, soul.md, LLM Wiki/knowledge base, repository docs, state store, session memory, compaction, just-in-time retrieval, and fresh-agent relays.

How we work

Context assembly

Start with standing instructions, Contract/Plan slice, current handoff/state, and relevant architecture. Retrieve deeper knowledge only when the next decision needs it.

Handoff pack

Include current task, decisions, changes, evidence/results, verification state, blockers/risks, source pointers, next action, and stop/escalation condition.

Compaction

Use as lossy historical reference, not canonical state. Compaction ≠ handoff.

Model/context learning

Measure model + context strategy by work type, quality, cost, retries, and rework. A smaller model with excellent context and verification may beat indiscriminate frontier-model use.
