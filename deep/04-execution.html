Boundaries

Execution may adapt local implementation inside the reviewed Plan. If a Plan assumption fails, route to Planning. If the target should change, submit a Contract proposal.

Patterns

  • single-agent iterative loop;
  • fresh-agent relay;
  • parallel independent workers;
  • Maker → Checker;
  • coordinated multi-agent orchestration.
More agents ≠ more agentic.
How we work

Give the worker

A bounded L3 task/L2 increment, relevant Contract + architecture + dependencies, fresh context/handoff, allowed capabilities/authority, and required evidence hooks.

Worker behavior

Use tools, inspect feedback, test continuously, retry where reasonable, capture state, and stop/escalate when evidence says the boundary or Plan is wrong.

Maker → Checker

Useful execution review topology. It does not replace lifecycle Validation against Contract Proof.

Open experiment

Whether Execution Loop deserves its own reusable skill remains intentionally unresolved; validate through real work.
